Início / 7. Glossário e perguntas frequentes

Glossário

Termos de negócio e técnicos, em linguagem simples

Resumo simples

Aqui estão as palavras usadas na documentação, explicadas de forma direta. Na primeira vez que um termo aparece em cada página, ele é sublinhado e leva até esta definição.

Termos de negócio

Arquivar (também: arquivado)
Esconder um gerador das listas sem apagá-lo do banco (exclusão lógica). O registro continua guardado.
Ativo (iClass) (também: ativos do iClass)
Um equipamento cadastrado no iClass. Um gerador da plataforma é ligado ao seu ativo pelo número do ativo (campo ativo_id).
Bitola
Medida do oxicatalisador de um gerador. A plataforma só registra o valor informado.
CFOP
Código fiscal da operação: identifica o tipo de venda ou circulação de um produto em documentos fiscais.
CNPJ e CPF (também: CNPJ, CPF)
Números de registro de empresas (CNPJ) e de pessoas (CPF) na Receita Federal. A plataforma usa o CNPJ ou CPF para reconhecer um cliente e ligar registros entre si.
CNPJ limpo
O CNPJ (ou CPF) escrito só com números, sem pontos, barra ou traço. É usado para ligar registros entre tabelas.
Código de integração
Código criado pela plataforma ao cadastrar um cliente (ATG_ seguido do CNPJ) para reconhecer o mesmo cliente no Omie e no iClass.
Conferência (também: status de conferência)
Comparação entre o cadastro do cliente e o que existe no iClass, que gera um status (OK, DIVERGENCIA ou NAO_ENCONTRADO). A lógica que decide esse status não está no código da plataforma; o código só exibe o valor e grava OK depois de uma correção manual.
Contrato (iClass) (também: código do contrato, contrato ativo)
Código com que o iClass identifica o cadastro de um cliente. Na plataforma aparece como código do contrato ou código do iClass. Na planilha de preditivas, a coluna "ativo" diz se o contrato está ativo.
ERP
Sistema de gestão de uma empresa (cadastros, vendas, faturamento). O Omie é o ERP da ATG.
Ficha de levantamento (também: ficha)
Formulário técnico (checklist de uma ordem de serviço do iClass) com dados do motor, bateria, filtros e outros componentes do gerador. A plataforma busca essa ficha no iClass e guarda uma cópia no gerador.
Gerador (também: geradores, grupo gerador)
Equipamento de geração de energia de um cliente, que a ATG mantém. Na plataforma, cada gerador é um registro ligado a um cliente e a um ativo do iClass.
iClass
Sistema de gestão de serviços em campo usado pela ATG. Guarda clientes, ativos (equipamentos), ordens de serviço e fichas de levantamento. A plataforma conversa com ele por uma API.
Inativar cliente (também: inativar, reativar)
Marcar um cliente como inativo sem apagar nada e sem mexer no Omie nem no iClass. O cliente pode ser reativado depois, reaproveitando os mesmos cadastros.
LC 116
Lista de serviços da Lei Complementar 116, que classifica cada serviço para o imposto municipal. O Omie guarda esse código em cada serviço.
NCM
Código de classificação fiscal de um produto, usado em notas e impostos.
Omie
Sistema de gestão (ERP) usado pela ATG para cadastro de clientes, produtos, serviços e orçamentos. A plataforma conversa com ele por uma API.
Orçamento (também: orçamentos)
Proposta de preço de produtos e serviços para um cliente.
Ordem de Serviço (O.S.) (também: O.S., OS, ordem de serviço, ordens de serviço)
Registro de um serviço a executar ou executado. Existe no iClass e também em uma tabela da plataforma.
Oxicatalisador
Componente do sistema de escapamento do gerador. A plataforma registra se o gerador possui e qual a bitola, mas não controla datas dele.
Perfil de usuário (também: perfis)
Tipo de acesso de quem entra na plataforma: administrador, usuário comum ou vendedor. O perfil define o que a pessoa pode ver e fazer.
Planilha de preditivas
Planilha de origem dos dados de manutenção preditiva. Foi importada para o banco, e o sistema tenta ligar cada linha a um gerador comparando nomes.
Preditiva (também: manutenção preditiva, preditivas)
Acompanhamento de itens de manutenção do gerador (troca de óleo e filtros, bateria, mangueiras, limpezas) com data realizada e data de vencimento. A plataforma mostra o que está em dia, a vencer ou vencido.
QTA
Sigla de um dos itens de manutenção preditiva ("limpeza do QTA"). O significado da sigla não está no código da plataforma.
Relatório de Saúde
Documento em PDF, gerado pela plataforma, que resume a situação de manutenção de um gerador: itens em dia, a vencer e vencidos.
Validado (também: validação)
Marca de que uma pessoa conferiu o cadastro de um cliente ou gerador e o aprovou.
Vendedor (também: vendedores)
Pessoa responsável comercial por clientes. Pode ter um login com perfil vendedor para ver os próprios clientes.

Termos técnicos

API
Forma de um sistema pedir dados ou ações a outro por meio de chamadas padronizadas. O Omie e o iClass oferecem APIs.
API REST (também: REST)
Forma comum de um sistema receber pedidos por endereços de internet. O Supabase oferece uma para ler e gravar as tabelas.
app_metadata (também: user_metadata)
Dois campos do cadastro de login no Supabase. O primeiro só o servidor consegue alterar e guarda o perfil e as páginas liberadas; o segundo a própria pessoa consegue editar e serve só para o nome.
Backup
Cópia de segurança dos dados, para recuperar se algo for perdido ou alterado por engano.
Build (montagem) (também: build)
Etapa que transforma o código do programador nos arquivos finais do site, prontos para publicar.
Cache
Cópia guardada pelo navegador ou por uma rede para abrir mais rápido. Às vezes mantém a versão antiga de uma página ou de um dado até ser recarregada.
CDN
Rede que distribui arquivos de sites a partir de vários locais, para carregarem mais rápido.
Chave estrangeira (também: FK)
Campo que aponta para a chave primária de outra tabela e garante que a ligação existe.
Chave primária (também: PK)
Campo (ou conjunto de campos) que identifica cada linha de uma tabela de forma única.
Commit (também: commits)
Um registro de mudança no Git, com um código curto (por exemplo, 8db54a9) e uma descrição. Permite voltar atrás.
Credencial (n8n) (também: credencial, credenciais)
Acesso guardado dentro do n8n (um token, uma chave ou uma conta autorizada) para um fluxo falar com um serviço. É o jeito seguro de guardar segredos; quando a chave está escrita dentro do fluxo, ela fica exposta.
Dado pessoal
Informação que identifica uma pessoa, como nome, telefone, e-mail ou documento. Na documentação do banco, esses campos recebem esta etiqueta.
Diagrama ER (também: ER)
Desenho das tabelas do banco e das ligações entre elas.
Easypanel
Painel de hospedagem onde o servidor do n8n roda.
Edge Function
Programa que roda no servidor do Supabase. Aqui é usada para gerenciar usuários (convidar, trocar senha, ativar e desativar), tarefas que o navegador não pode fazer com segurança.
Exclusão em cascata (também: em cascata, CASCADE)
Regra de uma chave estrangeira: ao apagar o registro principal, os registros ligados a ele são apagados junto.
Fluxo (também: fluxos, automação)
Sequência de etapas automáticas montada no n8n, com condições e ramificações.
Front-end (também: front)
A parte da plataforma que roda no navegador do usuário (telas, botões, formulários).
Gatilho (trigger) (também: gatilho, gatilhos, trigger, triggers)
Regra do banco que executa uma função sozinha quando uma linha é inserida ou alterada.
Git (também: GitHub, repositório)
Ferramenta que guarda todas as versões do código, com quem mudou o quê e quando. O GitHub é o serviço onde o repositório fica guardado.
HMR
Atualização automática da tela de quem programa, sem recarregar, enquanto edita o código.
HTTP
Protocolo da internet para pedir e receber dados. Os códigos de resposta indicam o resultado (por exemplo, 200 deu certo, 500 deu erro no servidor).
IDF (peso da palavra) (também: IDF)
Medida de quão rara é uma palavra entre os nomes cadastrados. Palavras raras pesam mais na comparação de nomes.
Índice (também: índices)
Estrutura do banco que acelera buscas por um campo, como o índice remissivo de um livro.
Integração contínua (CI) (também: CI, Docker)
Verificação automática do código a cada mudança (testes e montagem). O projeto não tem. Docker é outra ferramenta de empacotamento que também não é usada aqui.
JSON / JSONB (também: JSONB, JSON)
Formato de texto estruturado para guardar dados com vários campos dentro de um único campo do banco.
JWT
Tipo de token usado no login do Supabase: um texto assinado que diz quem é o usuário e qual o perfil dele. Vai junto com cada pedido que o navegador faz.
Limite de chamadas (rate limit) (também: rate limit, sobrecarregado, limite de chamadas)
Número máximo de chamadas que um sistema aceita por minuto. O iClass limita as chamadas, e a plataforma controla esse limite com uma contagem no banco para não ultrapassar.
Log (também: logs)
Registro automático do que um sistema fez. Não confundir com o Histórico de edições, que é o diário de negócio da plataforma.
Migration (também: migrations)
Arquivo que descreve uma mudança na estrutura do banco, para que ela possa ser repetida e registrada em ordem.
n8n
Ferramenta de automação em que os fluxos da ATG foram montados. Recebe chamadas da plataforma, conversa com Omie, iClass, Gmail e WhatsApp, e responde.
Nó (n8n) (também: nó, nós)
Uma etapa de um fluxo do n8n, como chamar uma API, decidir entre dois caminhos ou esperar alguns segundos.
npm e Node.js (também: npm, Node.js)
Ferramentas usadas por quem programa para instalar as peças do projeto e rodá-lo no computador.
OAuth
Forma de autorizar um sistema a usar uma conta (como o Gmail) sem entregar a senha da conta a ele.
Paginação
Mostrar ou buscar uma lista grande em partes (páginas), em vez de tudo de uma vez.
Papel anon e authenticated (também: anon, authenticated)
Os dois papéis que o Supabase usa para quem chama o banco: anon é quem não fez login e authenticated é quem fez login.
pg_cron
Extensão do banco que agenda tarefas automáticas dentro dele. Não está instalada neste projeto.
pg_trgm (similaridade de texto) (também: pg_trgm, trigrama)
Extensão do banco que mede o quanto dois textos se parecem, comparando pedaços de 3 letras. Usada para ligar nomes de clientes parecidos.
Política de acesso (também: política, políticas)
Regra de RLS que diz quem pode ler ou gravar numa tabela e sob qual condição.
PostgreSQL (também: Postgres)
O banco de dados usado pela plataforma, dentro do Supabase.
Proxy
Computador intermediário entre o usuário e a internet, comum em redes de empresas. Pode guardar respostas antigas ou bloquear endereços.
React, Vite, TypeScript e Tailwind (também: React, Vite, TypeScript, Tailwind)
As tecnologias com que o site foi construído: React monta as telas, TypeScript ajuda a evitar erros no código, Vite prepara o site para publicar e Tailwind cuida da aparência.
Reserva (fallback) (também: fallback)
Plano B do sistema quando algo falha. Nos catálogos de produtos e serviços, a reserva é uma lista de exemplo embutida no código.
RLS (segurança por linha) (também: RLS, Row Level Security)
Recurso do banco que decide, linha a linha, quem pode ler ou gravar. Quando está desligado numa tabela, quem tem permissão na tabela acessa todas as linhas.
Rota por hash (também: hash)
Forma de navegar entre telas em que o endereço termina em # e o nome da tela, sem recarregar a página.
RPC (função do banco) (também: RPC, RPCs)
Função escrita dentro do banco que a plataforma chama pelo nome. Faz um conjunto de passos de uma vez, como criar um gerador e registrar o histórico.
SECURITY DEFINER
Modo de uma função do banco em que ela roda com a permissão do seu dono, e não de quem a chamou. Por isso ignora as regras de segurança por linha.
service_role (também: chave service_role)
Chave de acesso total ao Supabase, que ignora as regras de segurança. Só deve existir em ambientes de servidor e nunca em arquivos compartilhados.
Sessão
O período em que a pessoa está logada. Fica guardada no navegador até ela sair ou expirar.
SQL
Linguagem usada para consultar e alterar um banco de dados.
Supabase
Serviço que fornece o banco de dados (PostgreSQL), o login dos usuários e funções no servidor para a plataforma.
Supabase Auth (também: Auth)
A parte do Supabase que cuida de quem pode entrar: guarda e-mails, senhas, convites e o perfil de cada pessoa.
Tabela de rascunho (staging) (também: staging)
Tabela onde os dados de uma planilha são colocados exatamente como vieram, antes de serem tratados e gravados nas tabelas definitivas.
Tempo limite (timeout) (também: tempo limite, timeout)
Quanto tempo uma chamada espera uma resposta antes de desistir.
Token
Código temporário ou secreto que prova quem você é ao falar com um sistema, sem precisar enviar a senha toda vez.
UazAPI
Serviço que permite a um sistema enviar mensagens de WhatsApp. É usado pelo n8n no fluxo de orçamentos.
Upsert
Gravar "inserir ou atualizar" de uma vez: se a linha já existe, atualiza; se não existe, cria.
URL (também: endereço do webhook)
Endereço de uma página ou serviço na internet.
UUID
Identificador longo e único gerado automaticamente (como 123e4567-e89b-...), usado em algumas tabelas no lugar de um número sequencial.
Vercel
Serviço de hospedagem de sites. A equipe informou que o site da plataforma é publicado nele.
View (visão) (também: view, views, visão)
Consulta guardada no banco que se comporta como uma tabela de leitura. Combina dados de várias tabelas e calcula campos.
View materializada
View cujo resultado fica guardado no banco e só é atualizado quando alguém manda (refresh).
Webhook
Endereço na internet que dispara um fluxo quando recebe uma chamada. A plataforma chama os webhooks do n8n para criar clientes, buscar ativos e outras tarefas.

Termos da plataforma

Comparação de nomes (match) (também: match, conciliação de nomes)
Processo que compara o nome de cliente da planilha de preditivas com os geradores do banco e dá uma nota de semelhança. Resulta em auto, revisar ou sem_match.
Exportação para Excel (também: xlsx, Excel)
Geração, no navegador, de uma planilha .xlsx com o que está na tela. Usa a biblioteca xlsx (SheetJS).
Histórico de edições (também: log de edições)
Registro de quem fez o quê, quando e com quais valores antes e depois. Permite reverter alterações feitas por tela.
Resposta simulada (mock) (também: mock, simulada)
Resposta de mentira que o sistema usa quando uma função do banco ainda não existe, para a tela não quebrar. A plataforma avisa com uma mensagem amarela.

Verificado em 2026-11-12 no commit 8db54a9. Documentação interna: descreve a arquitetura da plataforma e não deve ser publicada abertamente.
