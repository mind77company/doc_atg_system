Início / 4. Banco de dados

preditivas_atg

Itens de preditiva por gerador

tabela 6.573 linhas em 2026-11-12

Resumo simples

Uma linha para cada item de manutenção de cada gerador: quando foi feito e quando vence. A situação (em dia, a vencer, vencido) é calculada pela view vw_preditivas, não guardada aqui.

As linhas nascem de duas formas: pela importação da planilha de preditivas (função processar_preditivas) ou pelo botão de cadastrar a preditiva padrão de um gerador, que cria os 7 itens vazios com editado_manual = true e linha_planilha = 0.

Regras que o banco impõe

  • Gatilho trg_pred_touch: BEFORE UPDATE ON public.preditivas_atg FOR EACH ROW EXECUTE FUNCTION tg_touch_atualizado_em()
  • Regra de validação preditivas_atg_match_status_check: CHECK ((match_status = ANY (ARRAY['auto'::text, 'revisar'::text, 'sem_match'::text, 'manual'::text, 'sem_planilha'::text])))
  • RLS (acesso por linha): ligado, políticas: pol_pred_auth (ALL para {authenticated}, condição true).
  • Privilégios de tabela: papel anon = todos; papel authenticated = todos (fonte: consulta Q12).
  • Cada gerador só pode ter uma linha por item (restrição preditivas_atg_gerador_item_unique; há também o índice único parcial uq_pred_gerador_item, que faz a mesma coisa).
  • Cada linha da planilha só pode ocorrer uma vez por lote (import_id, linha_planilha, item_codigo).
  • RLS ligado, com uma política que libera tudo para usuários logados (pol_pred_auth).
  • O item tem restrição de valores no match_status (auto, revisar, sem_match, manual, sem_planilha).
  • Usada por salvar_preditiva processar_preditivas vw_preditivas dentro do banco.
